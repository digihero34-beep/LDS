# SOURCE ALIGNMENT: REQUIREMENT VS ENGINEERING DECISION

## Explicitly stated in the CipherSchools brief
- Build a focused LLD practice platform MVP.
- Learner journey includes choose → design → submit → feedback → review → retry.
- Small set of LLD problems.
- Learner can work on a solution using a chosen format.
- Submission status is visible.
- Feedback should be useful and explainable.
- Attempt history should support improvement.
- Core design should use clear classes/interfaces/responsibilities.
- Research and implementation should address evaluation ambiguity, evaluator variation, and slow/failing evaluation.
- Simple monolith is acceptable.
- Research note, design note, working prototype, tests, README, and AI_USAGE.md are required.

## Proposed implementation decisions in this pack
- Structured design-sheet submission.
- Optional future submission abstraction.
- Engineering Design Review Workbench visual identity.
- 3-column practice workspace.
- Evidence-first feedback block pattern.
- Specific entity names such as Problem, Attempt, Submission, Evaluation, Rubric, Feedback.
- `Evaluator` interface and concrete adapters.
- Suggested database tables/fields.
- Suggested API route shapes.
- Suggested status names.
- Suggested seed problem list.
- Suggested 2-day task breakdown.

These are recommended implementation choices and may be adjusted if the repository, time, or actual evaluation environment requires it.
